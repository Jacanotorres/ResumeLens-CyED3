## Interpretation

- **The four reference samples are accepted by the profile they were written for.** The transducer maps different spellings (`JS`, `React.js`, `Postgres`, `Apache Spark`) to a single canonical token, so the automata only see canonical symbols.
- **Near miss.** Sam Rivera covers the frontend categories of Full Stack Developer but has no backend or database, so the sequence stops in an intermediate state and is rejected by every profile.
- **More than one profile.** Jordan Lee covers every required category of DevOps Engineer and of Data Engineer, so both automata accept. The profiles are evaluated independently; ResumeLens does not pick one.
- **A rejection always means a missing required category.** Before recognition, the tokens are projected onto the profile alphabet and sorted in its canonical order, so tokens out of order or outside Σ never reach the automaton. The only way left to fail is a required category Cᵢ⁺ with no token, which is what the *Reason* column reports.
- **Shared skills do not imply a shared profile.** PYTHON, SQL and GIT appear in several profiles, but a résumé must cover every required category of a profile to be accepted. For example, the Data Engineer sample has PYTHON, POSTGRESQL and GIT, but it is rejected as Machine Learning Engineer because it has no data-processing or ML library.
- **Acceptance is not a ranking.** An accepted verdict only states that the explicitly written qualifications match the formal pattern; it says nothing about experience level or candidate quality.
